# Revision and delivery

## Read the actual comments

Open the latest reviewable version, including replies and updated selections. For every thread, record the slide identity, selected object, requested change, affected dependencies and a concrete check. A terse instruction such as “remove this” applies to the selected object. If a reply changes the scope, use the most recent clear instruction. Read enough of a resolved thread to preserve accepted decisions. Ask about a missing selection only when the page and neighboring content cannot identify it.

Use this private worklist:

| Review location | Requested visible change | Protected evidence | Acceptance test |
|---|---|---|---|
| Case figure, selected subevent | Identify its parent and match its active leaves to the signal | Sample axis, reference boundaries, original measurements | Two aligned interval lanes are legible and a viewer can locate each labeled primitive. |
| Paired traces, request to add bottom labels | Label the whole duration under each trace | Existing upper captions explain the relative phase lengths | Both readings remain visible, correctly ordered, and consistent with the lengths. |
| Result figure, selected note | Remove redundant explanation | Metric, scale, necessary qualifier, numeric values | Inspect both the source graphic and the rendered slide for a surviving copy. |
| Repeated brand mark | Place it on each requested slide | Citations, page numbers, evidence, image proportions | Count one intended mark per page and inspect the longest footer and the divider. |

Read the new instruction together with prior decisions on that object. Record whether it adds a second piece of information, replaces an earlier choice or restyles it. On the changed slide, test the requested edit and the protected interpretation separately. A layering request may intentionally put two objects in the same rectangle. Inspect their order, contrast and audience-facing text.

Keep the author's approval or comment history in its review thread. Keep production notes in a private worklist or accompanying source record. Retain talk notes for the speaker's scientific explanation. Advance the version identifier on the files and on the commentable review surface together. If a slide is removed, update ordering, notes, page numbers, links, cross-references and object-specific anchors.

## Prove the edit where it will be seen

- Verify source labels, quoted text, model names, chart arithmetic, denominators and the status of approximate vs. reference labels.
- Render every slide, inspect changed figures at projection size, then inspect the areas surrounding each edit. For a repeated edit compare representative cover, divider, result, dense reference and demo pages. An image difference restricted to the intended region is a strong check for a local edit.
- Reopen the exported deck. Verify native text and tables, chart data, vector embeds and their source counterparts, font behavior, linked targets, slide order and media relationships. A standalone image can be commentable as a whole and still require its SVG source to change individual labels.
- When a commentable review copy is part of the agreed delivery, open it and verify current page count, comment access and selectable objects. Inspect a rendered title, a dense figure and any page touched by a renderer-specific correction. Keep the editable PPTX as the presentation copy and preserve the requested commentable surface for iteration.
- When a PDF is requested, export it from the final versioned PPTX. Check matching page count and order, line breaks, wordmark stacking, figure scales, table headers, and media stills. Verify embeds in the PPTX and identify demo pages as still frames in the PDF. Align the visible version, filenames and review entry.
- Return the new version and a short description tied to page numbers. Include editable figure sources and a source/design record when those belong to the agreed deliverables. Report only the playback, font fidelity and editability actually tested.

## Test the recipient’s save workflow

Keep the main PPTX and editable sources in Newsreader and Inter while diagnosing a local loading or saving problem. Record the exact family and weight in the warning. Check that the intended files are installed or registered in the authoring environment and renderer. Inspect the names used by themes, masters, layouts, slides, tables, notes and embedded font entries. Verify embedding permissions and relationships, then retry an edit and save with the intended fonts.

When the recipient needs to save locally and the issue persists, deliver a separately labeled copy such as `Talk_v12_Windows-compatible.pptx`. In the SELA example, Times New Roman takes the title role and Arial the text role in that copy. Map semibold to bold as needed and clear obsolete font references there. Preserve native titles and tables and keep the editable SVGs in their original typefaces. Export the main PDF with the design fonts loaded; identify the matching edition if a PDF of the compatibility copy is also requested.

Render the affected pages to check line breaks, table headers, and title or footer fit. When target PowerPoint is available, use a machine without the custom fonts, open the file, edit one title and table cell, save under a new name, close and reopen it. Record the environment tested. Package inspection or a LibreOffice export establishes a different result than a Windows PowerPoint round trip.

## Maintain this skill after a seminar

Before adding a lesson, identify a final page or explicit current instruction that supports it. Classify the lesson as a transferable principle, a technique conditional on the evidence, or a named project's convention. When a decision changes, edit its authoritative paragraph and remove conflicting prescriptions from every reference, template, guide and example. Keep version history outside the reader-facing manual. A new release should read as one set of current instructions.
